# Spacing

One token: <code>--spacing: {spacing.base}</code>. Tailwind v4 multiplies it to
generate the entire scale, so `p-4` is four times {spacing.base} and there is no
list of hand-authored steps to keep in sync.

<Rule>
  **Do not add `--spacing-1`, `--spacing-2` and friends.** Naming individual
  steps is Tailwind v3 thinking; in v4 it produces a second scale that fights the
  generated one, and arbitrary steps like `gap-7` silently fall back to the
  generated value anyway. The base is the token. The steps are consequences.
</Rule>

## The scale

Each bar's width **is** the value — nothing here is drawn to a fixed size.

## Which step to reach for

The scale is continuous, but a design system is only coherent if everyone reaches
for the same rung. These are the defaults; deviate when the layout argues for it,
not by habit.

## Spacing does not change with mode

There is no light-mode spacing scale. Colour and elevation flip between modes;
geometry does not. A layout that needs different spacing in light mode is a
layout with a colour problem.
